# Convex Deploy Typecheck Fix

**Issue:** `npx convex deploy` fails typecheck  
**Root Cause:** Convex tsconfig extends root tsconfig which includes SvelteKit route files  
**Commit:** e4e8f10

---

## Problem

When running `npx convex deploy`, the Convex CLI runs its own TypeScript type checker over the `convex/` directory. The original `convex/tsconfig.json` extended the root `tsconfig.json`:

```json
{
  "extends": "../tsconfig.json",
  "compilerOptions": { ... }
}
```

The root `tsconfig.json` extends `.svelte-kit/tsconfig.json`, which includes `src/routes/**/*` in its compilation scope. This causes Convex to attempt to typecheck SvelteKit route files like:

- `src/routes/+layout.ts`
- `src/routes/+page.ts`
- `src/routes/dom/+page.ts`
- `src/routes/map/+page.ts`

These files import from `./$types`:

```typescript
import type { LayoutLoad } from './$types';
```

The `./$types` module is **generated by SvelteKit** during `svelte-kit sync` and lives in `.svelte-kit/types/`. However, Convex's build process doesn't run `svelte-kit sync`, so these generated types don't exist when Convex typechecks, causing errors like:

```
Cannot find module './$types' or its corresponding type declarations.
```

---

## Solution

Make `convex/tsconfig.json` **self-contained** so it only checks Convex files and doesn't inherit SvelteKit's route file inclusions:

```json
{
  "compilerOptions": {
    "module": "ESNext",
    "target": "ES2021",
    "lib": ["ES2021"],
    "moduleResolution": "bundler",
    "allowJs": true,
    "checkJs": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "skipLibCheck": true,
    "strict": true
  },
  "include": ["./**/*"],
  "exclude": ["../src", "../node_modules"]
}
```

**Key changes:**

1. **Removed `"extends": "../tsconfig.json"`** — no longer inherits SvelteKit's includes
2. **Added explicit `compilerOptions`** — duplicates necessary settings from root config
3. **Added `"include": ["./**/*"]`** — only Convex files
4. **Added `"exclude": ["../src", "../node_modules"]`** — explicitly excludes SvelteKit source

## Alternative Approaches Considered

### 1. Run `svelte-kit sync` before Convex deploy

**Pros:** Generates `./$types` so Convex can check route files  
**Cons:**
- Couples Convex deploy to SvelteKit build
- Unnecessary since Convex doesn't need to check route files
- Adds build time

### 2. Use `skipLibCheck: true` in Convex tsconfig

**Pros:** Simple one-line fix  
**Cons:**
- Skips checking all `.d.ts` files (too broad)
- Doesn't solve the root issue (missing generated types)
- Still tries to compile route files

### 3. Exclude `src/routes` specifically

**Pros:** Surgical fix  
**Cons:**
- Still inherits other SvelteKit config (like path aliases)
- Less explicit than self-contained config

**Chosen:** Self-contained config (solution above) is clearest and most maintainable.

## Lessons Learned

**Problem:** Monorepo-style projects (SvelteKit + Convex) need isolated TypeScript configs.

**Solution:** Don't extend root tsconfig from subdirectory projects. Each tool (SvelteKit, Convex, Playwright) should have a self-contained tsconfig that only checks its own files.

**Pattern:**
```
project/
├── tsconfig.json          # Extends .svelte-kit/tsconfig.json
├── convex/
│   └── tsconfig.json      # Self-contained, only checks convex/**
├── tests/
│   └── tsconfig.json      # Self-contained, only checks tests/**
└── src/
    └── (checked by root tsconfig via svelte-kit)
```
